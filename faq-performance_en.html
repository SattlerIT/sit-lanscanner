🔍 Performance test and scan load

This page describes how the LAN performance test works, what happens on the selected target and how to set the intensity of the network scan and of the follow-up search for missing devices.

What does the LAN performance test do to the target device?

It writes a test file to a folder that you choose, reads it back immediately and measures the time. Technically, this is the same as copying a file to a share in Explorer and fetching it back. No raw data is sent to a network port, no packets are generated and no ports are occupied. Only the target you have entered is addressed – a share, a network drive such as U:, or a local folder for comparison. A device you do not write to remains completely untouched by the test.

The amount of data transferred does not matter to the devices: network ports are galvanically isolated, and the transfer rate is fixed by the hardware. No program can push more through a connection than it can carry – so the test always stays within what the devices are built for.

What exactly happens during the performance test?

A measuring cycle consists of four steps that repeat until you press ⏹ Stop:

StepWhat happens
1. Write A test file _sit_lan_test.tmp of the selected size (1, 4, 16 or 64 MB) is written to the target folder, and the time is measured
2. Read The same file is read back immediately, and the time is measured again
3. Display Size and time give the write and read rate, which appear in the chart and in the log
4. Repeat The cycle starts again until you end it; then the test file is deleted
Small file, large file: 1 MB rather shows how quickly the network responds; 64 MB rather shows the actual sustained speed. 4 MB is enough for a first impression.

The NAS is asleep – why does the test wait first?

Many NAS devices spin down their disks during idle periods. On the first access they spin up again, which takes from a few seconds to more than a minute depending on the device. So that the test does not stop with an error during this time, the program waits before starting until the target responds. You set how long under ⚙ Config → “Wait time for network drives”: off, 30, 60 or 120 seconds. The default is 60 seconds.

Does the test put a load on my NAS or server?

For the duration of the measurement it creates continuous write and read activity – comparable to a scheduled backup run or a nightly synchronisation. The only difference is that it continues without a break until you end the test. On a device that someone is working with, their access may become slower. On a server in production use you should therefore not let the test run for hours.

Worth knowing: data really is written. On flash memory – such as an SSD NAS or a USB stick on the router – every write means a minimal amount of wear. For a few minutes of measurement this is negligible; the tool is not intended for a continuous run lasting days.

This is not a peculiarity of this program but lies in the nature of the task: if you want to know how fast files actually arrive, you have to write files and read them back – the drive at the other end has to answer. The Windows disk check and the test programs of drive manufacturers work the same way. Measurements without any writing do exist, but they only test the line, not the route your data takes in practice.

There is a file _sit_lan_test.tmp in the target folder – what is it?

This is the test file of the speed measurement. Normally it is deleted automatically after the test. If the connection drops during a measurement or the program is terminated forcibly, it may remain. You can delete it without concern.

Can intensive scans affect printers or routers?

Slow them down briefly: yes, that happens. There are no lasting effects. Small embedded devices such as printers, network cameras or older routers have only a very lean network component. Many simultaneous connection attempts can slow them down; in rare cases a restart of the device helps it to respond quickly again.

This is not a peculiarity of this program – Windows network discovery or a built-in tool such as ping can trigger the same reaction. Because network devices react with different sensitivity to requests, the scanner offers several levels that you can choose freely under ⚙ Config.

Scan intensityWhat is asked
SafeEach device by ping only – for sensitive networks
StandardPing and ARP – recommended
IntensivePing and ARP in two passes – finds more devices

The port scan is a separate switch. It checks a fixed list of common ports on each device found and uses the result to refine operating system and device type.

What does the follow-up search for missing devices do?

Some devices do not answer on the first attempt – because they are asleep, because their firewall rejects ping or because the Wi-Fi briefly stalls. The follow-up search therefore asks again after ping and ARP. Only addresses that have not answered so far are asked.

Follow-up searchWhat is asked
OffNo follow-up search – the scan ends after ping and ARP
Known addressesAddresses where a device was found in earlier scans are asked a second time, with more patience. Takes a few seconds. Default
All silent addressesIn addition, the program tries to connect to typical ports on all addresses without an answer – for example website, Windows sharing, remote maintenance, camera or printer. As soon as one port answers, the address is done. Also finds devices that do not answer ping, but takes longer
You decide how thoroughly to check. Because devices on a network react with different sensitivity, the scanner does not set the intensity itself but leaves it to you. Fewer methods mean fewer requests per device – and a faster run as a side effect. The price is the hit rate: a device that does not answer ping may remain undetected. In a network with sensitive devices, choose “Safe” and, for the follow-up search, “Off” or “Known addresses”.
